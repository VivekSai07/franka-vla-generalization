# Failures and lessons

Every failure that cost real time, with the fix and the commit. The actionable
pre-launch version is the checklist in [TODO.md](../TODO.md).

## Failures we hit (and what we learned)

1. **Expert failure counted as stop** — first broad_workspace run halted at 52/200 because a failed expert bubbled up as a hard error. Fix: wrap in `ExpertRejection`, bill to rejection budget (`57975c5`).
2. **Deleted the pilot manifest** during cleanup, breaking every downstream `provenance()` check. Fix: make manifest optional in `fixed_layout/source.py` (`57f558d`), then re-seal `local_varied_data` with post-surgery provenance and update `SEAL` constants (`f3f3244`).
3. **X-VLA reload verify used CPU + no autocast** — checkpoint verification hit `Input cuda / weight cpu` because obs came from the CUDA training path but the reloaded policy stayed on CPU. Fix: `.to('cuda')` + `torch.autocast('cuda', bfloat16)` in `_reload_and_verify` (`391049c`).
4. **LeRobot per-episode PNG staging accumulated across rejections** — rejected ep 52's 528 PNGs stayed under `episode-000052/`, so ep 53's writes gave 1056 files → encoder coverage check tripped. Fix: purge staging PNG dir + reset `episode_buffer` after every `ExpertRejection` (`4561995`).
5. **Attempts dir naming diverged from LeRobot's episode_index after rejections** — encoder read ticks from `attempts/000052/` (rejected) while PNGs came from ep 53. Fix: expose `dataset._active_attempt_path` set in `record_attempt`, use it in the encoder wrapper (`2435dca`).
6. **Validator hard-coded `slot['episode_index']+1` as expected admit count**, which no longer matched LeRobot's `total_episodes` post-rejection. Fix: read `info.json['total_episodes']` as the count and let the remaining `_metadata` invariants (schema, task, fps, frame count) do the checking (`3d733d2`).
7. **Preflight scratch dir deleted** to free disk before eval → `verify_final` couldn't hash `SCRATCH/result.json`. Fix: make scratch check conditional in the eval package (`c8a6904`). The preflight `result.json` had non-deterministic timing fields so it wasn't reproducible.
8. **Editing source files while eval was still running** → final `c.admission()` re-check saw drift and marked the run "failed" even though all 92 rollouts had already completed cleanly. Lesson: freeze the code path for the duration of the eval.
9. **Rejections skipped the slot instead of retrying it** — this was the root cause behind three separate 35-hour collection failures at the same point. Slot index doubled as the admitted-episode index, and `metadata[i]`, `attempts/{i:06d}`, `resets/episode_{i:03d}` and the train/val split boundaries all depend on `slot == admit`. Skipping broke every one. Fix: retry the same slot until admitted (`3926614`).
10. **The tests asserted the buggy behaviour.** 35/35 passed while production died three times identically, because `test_expert_execution_failure_billed_to_rejection_budget_not_stop` demanded `len(admitted) == 198` — i.e. it *required* slots to be skipped. Rewrote the tests to assert correct behaviour and added a regression test that runs `validate_journal` over scheduler output. Green tests are not evidence when they encode the defect.
11. **Two layouts were physically uncompletable / irreproducible.** `validation_020` failed all 16 expert attempts (cube 2.0–2.1 cm off, admitted episodes ≤1.74 cm). `validation_032` stacked fine but its grasp geometry made the float32 replay drift 1.51e-3 (tolerance 1e-3) *identically on every redraw* — variance <1e-8 across independent ±1° jitters, proving it systematic rather than chaotic, so no amount of redrawing could fix it. Fix: deterministic layout resampling inside the same envelope (`76d8e91`, `c429b1d`). Both fall in the validation split, so the 160 training episodes are untouched.
12. **Resume, rollback and unique rejected paths** — a crash at 179/200 would have discarded everything. Added `resume_state` + `amend_frozen_plan`, episode rollback with stats re-aggregation for drift rejections (`91cc4cf`), and unique `rejected/{i}_k{k}_r{n}` paths after a rename collision killed a run (`7807c7c`).
13. **The evaluation inherited pilot-era workspace bounds.** `restore_scene` gates on `pilot_integrity.validate_scene_geometry`, which caps |y| at 0.40 m — but envelope F7 reaches 0.45 m. Scene derivation was provably correct (every per-array SHA256 matched the sealed bank) yet 12 of 36 holdout layouts were rejected, precisely the widest and most discriminative ones. Relaxing the shared validator would have invalidated the sealed provenance of every dataset, so the eval packages restore with the collector's own F7 geometry gate instead (`e11c784`).
14. **A holdout failure is not automatically a policy failure.** The 80 reserved layouts were never expert-verified, and 8 of them failed X-VLA on both seeds — indistinguishable from an unsolvable layout. Screening all 8 with the scripted expert showed every one is solvable, which is what makes 68.1% reportable. Do this screening before reporting any systematic failure cluster.

15. **The runner hardcoded the training horizon separately from the contract.** `recipe()` was changed to 16700 updates and every contract test passed, but `runner.py` had its own `maximum = 2 if preflight else 5000`. The run trained exactly 5000 updates, wrote checkpoints `[1, 2000, 4000]`, and only failed *afterwards* on `verify_checkpoints` — ~70 min of GPU wasted. The tests missed it because contract tests asserted `recipe()` while runner tests used synthetic checkpoint fixtures; nothing tied the loop bound to the recipe. Fix: derive `maximum` from `c.recipe(False)['max_optimizer_updates']`, plus a regression test asserting the runner contains no `else 5000` and that horizon / final checkpoint / LR-schedule total all agree (`4f7d621`). **Verify such a test actually fails against the pre-fix code** — this one was checked with `git stash`.
16. **Editing any `SOURCE_FILES` member invalidates the recorded admission.** Fixing `runner.py` meant the relaunch correctly refused with "Current full CPU admission required", forcing a ~1h re-`--check` and a fresh `--preflight`. Not a bug — the gate working — but budget for it: a one-line runner fix costs a full admission cycle.
17. **A hash-bound README nearly killed a finished 3-hour evaluation.** `broad_workspace_data/scenes.provenance()` explicitly appends its own README (`paths += [Path(__file__).with_name('README.md')]`). Editing it to mark collection complete would have failed the eval's final `c.admission()` after every rollout had already succeeded. Caught and reverted; provenance and binding re-verified. **Consequence: that README, and `experiments/{xvla,smolvla}_local_varied/README.md`, can never be corrected** — the latter two permanently state seal `f8b10a49…` when the actual is `ae8828ea…`.
18. **A stale `git worktree` silently ran old code.** The historical-source worktree used for cross-evaluation was created at an earlier commit, so it kept executing a superseded `c.admission()` path long after the fix was committed — presenting as a logic bug. It also could not simply be refreshed, because another run was live from that same mount. Check `git log -1` inside a worktree before blaming the code.
19. **Long-running jobs were left unmonitored.** A training run failed and sat dead for 47 minutes because completion was assumed rather than checked. `docker wait` has also silently failed to notify in this environment. Poll actively at each stage; do not treat "launched" as "will report". Fixed structurally by chaining train → verify → evaluate in one detached host script that refuses to start the evaluation unless the training report verifies.
20. **An evaluation package was hard-bound to one training run.** `xvla_broad_workspace_eval` pins `completed_updates: 5000` and validates `--checkpoint` against the short run's schedule, so it could not evaluate the matched-exposure run at all — it would have aborted at the first gate. Forking it was correct (`2c7a90c`), but two traps came with the copy: the horizon had to be *derived* (`recipe(False)['max_optimizer_updates']`, asserted against `checkpoint_updates(False)[-1]`) rather than re-hardcoded, and the copied tests still imported the **old** module, so they passed 26/26 while testing entirely the wrong code. That is meta-lesson #1 for the fifth time.
21. **Offline metrics do not predict task capability — they actively mislead.** On the matched-exposure run, train/val arm MAE improved monotonically (0.03390 → 0.02621 → 0.01022) while rollout success went 25.0% → **0.0%** → 86.1% on the identical holdout. At update 8,000 the policy still grasped 72/72 but lifted only 17/72, leaving the cube a median 63 cm from target — a total capability collapse invisible in the loss, the MAE and the gripper accuracy. Never select checkpoints, stop early, or report progress from offline probes. Only rollouts count. Corollary: mid-training checkpoint evaluations are not a cheap substitute for the endpoint, and a val/train ratio is not by itself an overfitting signal.
22. **A predicted control turned out not to be a control.** The matched-exposure run was given a checkpoint at update 4,000 specifically to compare against the short run's 4,000 and isolate LR-schedule effects from exposure. It does not: at that update the short run sits at lr 2.05e-5 (80% annealed) and the long run at 9.00e-5 (24% annealed), so the pair compares different schedule phases and is unsurprisingly indistinguishable (15/72 vs 18/72, p = 0.69). The LR-matched pair is short@4000 against long@12000 (2.74e-5). Lesson: when matching runs for a comparison, match the *schedule phase*, not the raw step count — checkpoint schedules should be chosen from the LR curve, not from round numbers.
23. **A plausible root-cause hypothesis, refuted by data.** The 10 remaining failures at 86.1% are a strikingly consistent 4.51 cm ± 0.20 cm placement offset — one cube width, cube set down beside the target rather than on top. The natural explanation was that the policy imitates an imprecise expert. Checking all 200 sealed demonstrations refuted it outright: expert mean final error 0.679 cm, max 1.981 cm, **zero** episodes above 2 cm, mean signed offset 0.1 mm, and a correct stack height in 200/200. The offset is policy-side. Recorded because the hypothesis was reasonable, cheap to test, and wrong — and because it changes the plan: more episodes of the same kind should not be expected to fix it. A second intuition died alongside it: the failures were assumed to be far, hard-to-reach layouts, but failing layouts average 0.424 m reach against 0.472 m for fully-solved ones — the far layouts are solved.

Broader lessons — every "just increment a counter" or "just leave state alone on retry" assumption in the fixed-layout pipeline broke under broad_workspace retries. Rejections need explicit cleanup for every piece of shared state (LeRobot buffer + PNG dir + attempts dir semantics + admit-count invariant). And a result is only interpretable once you know what the *absence* of the treatment scores on the same protocol.

**Recurring meta-lesson — a green test suite is not evidence.** Five separate times (#10, #15, #20, and twice while porting eval packages) the tests passed while the thing that actually runs was broken, because the tests exercised a *fixture*, a *constant*, or the *wrong module* rather than the production path. When adding a regression test, confirm it fails against the unfixed code.

**Second meta-lesson — know what is hash-bound before editing.** Provenance and `SOURCE_FILES` reach further than expected: into READMEs (#17), into shared helpers used by four contracts, and into files a live run re-hashes at its final gate (#8, #17). Check membership before touching anything while a job is running.

**Third meta-lesson — measure the thing you care about.** Loss, MAE and gripper accuracy all improved while the policy became completely incapable (#21). Every cheap proxy adopted so far has eventually diverged from rollout success. Budget for real rollouts; treat proxies as debugging aids only.

# B1 language grounding — design

**Date:** 2026-09-24
**Status:** design approved (Option C, 2×2 factorial); budgets below pending review
**Supersedes:** the one-line B1 entry in [TODO.md](../../../TODO.md), which would have produced a false positive

## Why the obvious experiment would have failed

The original plan was: *collect reversed-instruction episodes (green onto red) over the same layouts.*
That cannot work, because of a confound in the existing data.

`broad_workspace_data/plan.py` draws the two cubes from **disjoint** regions:

```
RED_LOW/HIGH   = (.20, -.45) .. (.35, -.20)    red is always at negative y
GREEN_LOW/HIGH = (.20,  .20) .. (.35,  .45)    green is always at positive y
```

Verified against the sealed data: in **200/200** training episodes and **80/80** reserved evaluation
layouts, red is at negative y and green at positive y, separated by a **40 cm gap**.

Consequently the pick target is perfectly predictable from `sign(y)`. "Pick the cube at −y and place
it on the cube at +y" solves 100% of the dataset. **The language pathway has never been
load-bearing**, so the 86.1% spatial result says nothing about it.

With red fixed at −y and green at +y, simply reversing the instruction makes
"red→green" ≡ "pick −y" and "green→red" ≡ "pick +y". A completely colour-blind model scores 100%
by learning *instruction → side*. The test would pass and the conclusion would be wrong.

## Design: 2×2 factorial

**Factor 1 — instruction.** `I_RG` = "red onto green", `I_GR` = "green onto red".
**Factor 2 — arrangement.** `familiar` = red in region A (−y), green in region B (+y), matching all
existing data. `swapped` = green in A, red in B.

The envelope, expert and spatial distribution are unchanged; only which colour occupies which
region varies.

| cell | instruction | arrangement | correct cube in |
|---|---|---|---|
| C1 | red→green | familiar | region A (−y) |
| C2 | red→green | **swapped** | region B (+y) |
| C3 | green→red | familiar | region B (+y) |
| C4 | green→red | **swapped** | region A (−y) |

Each region is correct in exactly 2 of 4 cells, and each instruction maps to region A once and
region B once. **Neither position nor instruction alone is sufficient; only instruction × colour
resolves all four.**

### The pattern is diagnostic, not just pass/fail

| cells passed | strategy the model is using |
|---|---|
| all four | genuine colour grounding |
| C1, C3 | instruction → **side** mapping — looks like grounding, is not |
| C1, C2 | always picks red; ignoring the instruction |
| C1, C4 | always picks region A; ignoring instruction and colour |
| C1 only | reproduces training, no generalisation |

The sharpest single contrast is **C1 vs C2**: same instruction, colour relocated. A drop there is
position-dependence.

## Feasibility

No expert changes are needed. The scripted expert is already colour-parameterised:

- `GraspController(model, data, target=f"target_cube_{episode['pick']}")`
- the instruction text is generated by `instruction(episode["pick"], episode["place"])`
- `stack_metrics(model, data, episode["pick"], episode["place"])`

The only change is in the collection plan, which currently hardcodes
`pick='red', place='green', instruction=TASK, task_index=0`.

## Collection

- **200 episodes, 50 per cell**, 160 train (40/cell) / 40 validation (10/cell).
- **200 distinct layout geometries, one episode each**, with the cell assigned per geometry and
  balanced across the four. Training needs no within-geometry pairing, so spending geometries on
  repetition would waste the spatial diversity that is already established.
- **Fresh collection, not mixed with the existing 200.** Those are all cell C1; combining would
  leave training 5:1 imbalanced toward the familiar arrangement, which is the exact shortcut the
  design exists to remove.
- **The plan must reserve the same 80 evaluation layouts** as `broad_workspace_data`, so the
  holdout is shared and the C1 cell is directly comparable to the sealed 86.1% result.
- `task_index` must vary with the instruction, and the instruction string must be derived from
  `pick`/`place` rather than hardcoded.

## Training

X-VLA only. SmolVLA is deferred: it is the weaker learner at every previous stage, and running both
doubles the bill to answer a second question.

160 training episodes × 499 complete starts = 79,840 starts. At the established 1.67 epochs and
effective batch 8 this is **16,700 updates — identical to the matched-exposure run**, which makes
B1's spatial performance directly comparable to 86.1% rather than confounded by a different budget.

Train from the **base bundle**, not from the broad-workspace checkpoint: that checkpoint has a baked-in
position shortcut, and fine-tuning from it would confound "can this architecture ground language"
with "can it unlearn a shortcut".

## Evaluation

**16 held-out geometries × 4 cells × 4 seeds = 256 trials**, drawn from the 36 layouts already used
for `broad_holdout` so that C1 is protocol-identical to the sealed result.

Seeds: T2a established that ≥8 seeds are needed for **per-layout** claims. B1's claims are
**per-cell aggregates pooled over geometries**, so n per cell = 16 × 4 = 64 without needing 8 seeds
per cell.

**Report geometry-clustered intervals, not naive binomial.** T2a measured per-geometry success
ranging from 12.5% to 87.5%, so trials cluster strongly within geometry; a naive interval would
overstate precision in exactly the way the 2-seed estimates did.

## Budgets

Measured rates: collection 1.97 min/episode (including rejections and failures), training
0.83 s/update, evaluation 2.2 min/trial.

| stage | quantity | cost |
|---|---|---|
| collection | 200 episodes | **6.6 h** |
| CPU admission (`--check`) | — | ~1 h |
| preflight | 2 GPU updates | ~5 min |
| training | 16,700 updates | **3.9 h** |
| evaluation | 256 trials | **9.4 h** |
| **total** | | **~21 h** |

Alternative sizes if the budget changes: 160 episodes → 5.3 h collect + 3.1 h train;
400 episodes → 13.1 h collect + 7.7 h train.

## Confounds and controls

**Data starvation.** Splitting 160 training episodes across 4 cells gives 80 per instruction against
160 for the single-instruction model. A lower absolute score could be thinner data rather than
language difficulty.

The key diagnostic is nevertheless safe: **C1 vs C2 is a within-model contrast** — same weights,
same data budget, same instruction — so attribution of a drop to position-dependence holds
regardless of the absolute level. Only the *absolute* "does grounding work" claim is exposed.

Decision: collect 200 first. If absolute performance is ambiguous (all cells depressed, no clear
signature), escalate to 400 episodes so each instruction gets the full 160. Do not pay for the
control up front.

**Novel visual configuration.** The swapped arrangement puts a red cube at +y, which no existing
checkpoint has ever seen. This is intended — it is the manipulation — but it means B1's model must
be trained on both arrangements. Evaluating an *existing* checkpoint on C2/C4 would measure
distribution shift, not grounding.

## Success criteria

- A determinate signature in the 4-cell table, with geometry-clustered intervals that separate at
  least the C1/C2 contrast.
- C1 comparable to the sealed 86.1%, confirming spatial capability was not lost.
- A defensible answer to "does this architecture ground colour from language, or does it follow
  position" — including "it follows position", which is a result, not a failure.

## Non-goals

- SmolVLA (deferred).
- Fixing the 4.5 cm placement offset — orthogonal, see
  [2026-09-24-placement-offset-design.md](2026-09-24-placement-offset-design.md).
- Distractors and full colour randomisation (B2, B3).
- Re-sealing or modifying `broad_workspace_data`.

## Open decisions

1. Collection size: 200 (recommended) vs 400 up front.
2. Whether to also evaluate the existing broad-workspace checkpoint on C1/C3 as a baseline —
   cheap (~2 h) and would confirm the position shortcut empirically rather than by inference.
